# SoloDirector 工程审查与比赛准备

审查日期：2026-09-21。Codex 负责设计取舍、复核与提交；具体实现委托本机 Claude Code。

## 验收标准

1. 单元测试覆盖合法/非法事件时间、三类事件正负样例与连续性。
2. 真实 FFmpeg 合成视频 + 确定性姿态输入验证 JSON、照片、片段与高光文件。
3. 真实 YOLO 权重单独验证可加载与推理；合成画面不能证明真人动作识别准确率。
4. 分析任务各自产物互不覆盖；API 不允许客户端指定任意配置文件与输出位置。
5. C++ 桥接具备可验证的模拟连接生命周期；SDK 未配置时明确失败。

## 初审问题

| 问题 | 影响 | 验收依据 |
| --- | --- | --- |
| 全程保留全分辨率帧 | 4K 长视频内存迅速增长 | 仅保存元数据，最佳帧按需读取 |
| 分析共用输出文件名 | 第二次任务覆盖第一次结果 | 连续运行两次，分别读取产物 |
| 上传路由同步执行推理 | 阻塞服务事件循环 | 线程执行并限制并发分析 |
| 请求可指定配置和任意本地路径 | 输入/输出边界不明确 | 拒绝越界、符号链接、配置覆盖 |
| 稳定姿态每三秒截断 | 连续保持事件尾部丢失 | 长保持测试覆盖完整时间段 |
| 关键点可见性切换造成跳跃 | 错误基线产生假事件 | 双髋点、缺失重置、正负测试 |
| 事件 schema 接受未知类型和错序时间 | 前端拿到非法事件 | Pydantic 有限数、枚举、顺序校验 |
| FFmpeg 单引号转义错误 | 部分路径无法合并 | 含空格/单引号路径真实合并 |
| Mock 录制状态随进程退出丢失 | start/stop 无法联调 | 同进程会话连接、录制、停止 |
| Mock 下载文本假装 MP4 | 输入不能被视频工具读取 | 无素材时明确不支持 |

## 保留的产品与平台边界

- 当前主要人物由置信度等简单指标选取，没有稳定身份跟踪；多人、遮挡和镜头移动仍需真实样本评估。
- 稳定姿态事件在连续片段结束或分析结束时结算；实时自动快门需要另加触发通知，不能把离线事件等同于现场快门控制。
- 跳跃规则依赖画面中双髋的纵向移动，不足以证明脚离地；相机运动、蹲起仍可能产生误检。
- 评分为可解释启发式分数，不是标注数据上校准的概率。
- API 首版为本机单进程服务，任务状态内存保存；进程重启后状态丢失，文件仍可保留。
- 官方 Insta360 SDK 不在仓库。平台、架构、相机型号、固件、USB 模式、许可证与媒体导出能力须按比赛实际 SDK 验证。不能假设 macOS 一定支持 Desktop Camera SDK。
- 全景原始文件可能需要官方 Media SDK 拼接/导出后再给 OpenCV；普通 MP4 的离线能力不能替代 SDK 接入验收。

## 接下来三项工作

1. 真实素材校准：录制单人静止、举手、跳跃及负例；手工标注时间窗口，统计误报/漏报，冻结 demo 配置。
2. 真机接入：取得 SDK、目标设备和授权；依次验证连接、状态、录制、停止、文件列表、最新素材、下载与可解码导出。
3. 前端联调：基于事件 schema 与媒体接口展示时间线，验证重复分析、失败提示、预览与导出；准备固定演示样片和离线回退。

详细验证结果在本轮代码完成后更新；未完成项目不视为通过。
